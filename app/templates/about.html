Architecture

PromptGuard protects LLM applications from direct and indirect prompt injection with two separate ideas. Detection asks whether an input looks malicious. Capability control asks what the model is allowed to do if a malicious instruction reaches it anyway

Defense in depth

No detector catches every prompt injection. It is an adversarial problem, and reworded or new attacks can get past the rules, so PromptGuard layers independent controls and a miss in one can be caught by another.

Operating modes

  • LEARNINGdetect and log only
  • MONITORblocks become warnings
  • ENFORCEfull policy

Modes only change the input detector. The tool firewall and output firewall are always enforced.

Trust model

TRUSTED_SYSTEMUSER_INPUT UNTRUSTED_DOCUMENTEXTERNAL_CONTENTTOOL_OUTPUT

Untrusted content is wrapped in nonce-keyed fences and treated as data. Anything derived from it stays tainted, and tainted content cannot trigger sensitive tools.

Reference

Inspired by the concepts in the prompt-injection-firewall project by CarterPerez-dev. PromptGuard is an independent reimplementation and no source code was copied.
